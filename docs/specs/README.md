# Specification-Driven Development

For each feature: read `spec.md`; confirm scenarios and acceptance criteria; update contracts; write tests from criteria; implement the smallest conforming change; run tests and validate the demo; update specs and decision log when behavior changes.

The PRD defines product-level requirements, feature specs define implementable behavior, and tests provide executable verification.

- `001-automotive-demo`: dashboard and context propagation
- `002-chat-widget`: embeddable widget behavior
- `003-chat-api`: HTTP API contract
- `004-knowledge-retrieval`: knowledge records and ranking
- `005-llm-integration`: optional provider behavior
- `006-safety-behavior`: cautious automotive responses
